# 0.1.8-test · DLNA 与 AirPlay 合并测试版

基于原主应用 0.1.7-test 和独立镜像实验 alpha2 合并，一个 APK、一个启动图标。原包名 `cn.local.livingroomcast`、测试签名保留，versionCode 9，可以覆盖旧主应用。历史独立镜像实验包不会被覆盖或自动卸载。

## 两种模式

- **视频 App 投屏（默认）**：在发送端视频 App 里点 TV／投屏，选择“小狗便利店投屏”。保留触摸操作、可拖动进度条、六档倍速、真实画质显示、来源画质选择和后台待机。
- **AirPlay 镜像（测试）**：先点接收端主界面“AirPlay 镜像（测试）”，再在 iPhone／iPad 控制中心选择“屏幕镜像 → 小狗便利店投屏”。进入时停止 DLNA；返回视频投屏后恢复 DLNA。两种模式不同时接收。

模式切换会断开当前连接。镜像请保持界面打开；Home 或离开界面会停止 AirPlay，重新打开应用默认进入视频投屏。后台待机仅保留在 DLNA 模式；没有开机自启。

## AirPlay 范围

复用 alpha2 的音频输出重建、视频时间戳呈现、控制连接与媒体会话区分，以及连接详情中的“恢复声音”。请求最高 1920×1080／30fps，按来源比例显示。

支持入口是控制中心屏幕镜像。未保证视频 App 内 AirPlay 按钮、单独音频、ALAC、DRM、真实 4K 或低延迟游戏。音频修复是否消除用户此前 YouTube／相册无声及偶发加速，仍需原设备复测，不能把合并本身当作故障已解决。

## 系统和安装

本合并 APK 提供 arm64-v8a、armeabi-v7a。DLNA 仍最低 Android 6.0；AirPlay 原生依赖需要 Android 7.0 及以上，旧系统入口只给出说明，不加载镜像引擎。Android 6.0 与 32 位 ARM 的合并包运行效果尚需真机验证。

两端接入同一家庭局域网；首次升级后打开一次。测试时先退出旧的独立镜像实验包，避免同一台设备出现两个接收服务。独立镜像包的配对记录不会自动迁移。

## 本轮验证（2026-10-24）

- Android 12 ARM64 模拟器：40 项 AirPlay／合并原生检查通过，覆盖真实 mDNS、RTSP、合成音视频到 Surface／AudioTrack、恢复声音、单图标、反复切换、Home 停服及重新打开恢复 DLNA。
- 较小触摸屏 960×540／density 240 下，另有 3 项合并模式检查及 61 项播放控制通过；等待页可滚动至 AirPlay 入口，镜像按钮按小屏布局。
- 原 DLNA 的 61 项进度／倍速控制、38 项画质／信息层、28 项后台待机回归通过；29 项协议、10 项格式与 8 项画质模型检查通过。
- 52 项镜像单元检查通过，包括 API 23 禁用 AirPlay、API 24／ARM 放行与不支持架构保护。旧系统保护为代码与单元检查，未在真实 Android 6.0 设备运行合并包。
- 构建通过；宿主与镜像库 Lint 均为 0 错误，分别 18／20 个警告（依赖、目标版本、备份、硬编码文本、设备标识及常见 API 提醒等）。
- 快速从镜像返回只触发宿主 onResume 的情况曾导致 DLNA 不恢复，现已在恢复回调重绑定；快速与普通返回路径均已回归。
- 这些是合成媒体与模拟器证据，不代表真实 iPhone／iPad 握手、Sony 真机、长时间声画同步或所有视频 App 兼容性验收。
