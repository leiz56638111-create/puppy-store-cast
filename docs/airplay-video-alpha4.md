# AirPlay alpha4：遥控器导航修复与 B站排查结论

版本0.3.0-video-alpha4／versionCode4，独立包名cn.local.livingroomcast.airplayvideo，原签名可覆盖alpha3，不覆盖主版0.1.8。设备名仍为“小狗便利店投屏·AirPlay测试”，设备标识和配对文件沿用alpha3。最低Android7 ARM；32位只做编译检查。尚未上传GitHub。

## 已取得的真机结果

用户反馈alpha3中已测试的iPhone相册视频均可播放，样本数、格式和长时间指标未记录。用户随后确认：同一Bilibili视频，先断开App内隔空播放、再用控制中心屏幕镜像，电视的画面和声音都正常。这两个结果分别记录，不能把屏幕镜像通过写成B站App内AirPlay视频直投通过。

本次照片IMG_6517显示alpha3、Sony BRAVIA 4K VH21／Android12／API31：媒体连接1次；ct=2／usingScreen=false／isMedia=true；有效地址直投请求、到达视频处理器的请求、解析拒绝、设备查询、反向通道、播放列表响应和未处理协议请求均为0；视频流协商未完成，画面0×0，首帧／视频输出为0。

这表明当前可观测到的连接只协商了ALAC音频，未进入地址直投或编码视频流播放。加ALAC解码只能改善声音，不会补出未建立的视频路径。B站App内外播路径仍未兼容，尚不能确定是App选择了纯音频输出，还是设备识别／协商差异导致；不归因为DRM、会员、电视性能或解码器故障。当前已由用户验证的B站可用方式是**控制中心屏幕镜像**。

## alpha4实际修正

- 等待页主动把焦点交给“连接详情”；隐藏并禁止后台播放器参与焦点导航。
- 等待页和视频流菜单的两个按钮明确建立上下左右切换关系；确认／Enter可执行操作，按钮以绿色高亮显示选中。
- 播放方式改变时只恢复一次合适焦点，不让每250ms的状态刷新抢走用户选择。打开／关闭详情、从视频回等待、Home后重开均恢复可用焦点。
- 视频流按钮自动显示约2秒；开始遥控操作后保留约6秒，便于移动和确认，之后自动收起。触摸仍可用。
- 地址直投时“上”可选中详情，“下”回播放器暂停／继续控制；播放器其余标准控制仍由Media3处理。
- 连接详情使用上下滚动内容，确认或返回关闭。无需依赖遥控器菜单／设置键。

本轮不修改发现功能位、配对身份、HLS／视频流／音频解码协议或引擎；相册使用的alpha3接收路径保留。B站App内AirPlay没有作为已修复功能发布。

## 安装及验证

1. 覆盖安装alpha4并打开，确认“连接详情”有绿色高亮。
2. 等待页尝试上下／左右切到“退出测试”，再切回，确认打开详情、上下滚动、确认关闭；最后可确认退出。
3. 相册投送视频后，用方向键唤出菜单，切换详情／结束并确认；结束后应回到等待页并选中详情。
4. 继续复测相册实际画面／声音；B站先用已经验证可用的屏幕镜像。App内直投仍是单独待解决问题。

自动检查使用真实按键事件，覆盖等待页、模拟音频会话后、视频流菜单、结束接收、地址直投暂停／恢复和详情。其余MP4／HLS／发现／反向协商／换片／视频流实际帧和AAC输出继续回归。最终13项原生检查通过，直投单元3项／镜像库单元52项通过，Lint 0错误／11警告；按键检查明确使用D-pad输入源，且等待详情窗口关闭、主窗口重新获得输入焦点后继续操作。APK哈希见随包验收JSON；模拟器测试不等于索尼遥控器真机通过。alpha4本身尚待真实苹果／电视复测。

参考Android官方遥控导航规则：https://developer.android.com/training/tv/get-started/navigation 。历史IJK issue https://github.com/bilibili/ijkplayer/issues/2904 有类似音频路由现象，但发表于2017年，不能用它证明当前B站App仍使用同一引擎或本故障根因。
