# AirPlay 兼容接收测试版 0.3.0-video-alpha3

这是会改动接收／播放路径的独立实验更新。包名仍为 `cn.local.livingroomcast.airplayvideo`，versionCode3，原签名可覆盖 alpha1／alpha2，不覆盖公开主版0.1.8。最低 Android7／API24，ARM64与32位ARM；32位未真机运行。尚未发布GitHub。

## 本次针对的反馈

用户确认：iPhone相册播放单个视频，点隔空播放找不到接收器；Bilibili（B站）App可找到并选中，选中后没有画面。B站具体版本／视频类型和iPhone系统小版本未提供。旧包只接收HTTP(S)地址／HLS，关闭屏幕视频流功能广播，onVideoData／onAudioData为空回调，确实无法处理发送端选择的编码视频流。alpha2仅纠正提示并补充诊断，没有修复这一接收能力缺口。

上游 jqssun/android-airplay-server 同时保留视频流与地址／HLS接收。本轮补回真正的视频流解码与显示后再启用相应广播，不能仅打开广播却仍忽略数据。这个差异是实际代码事实；**是否正是当前相册隐藏设备与目标App不播的全部原因，尚无真实设备证据**。上游 UxPlay 也有新iOS仅协商音频而不发视频的公开反馈，不能承诺本包消除所有问题。

## 使用

1. 退出其他投屏接收器，包括主版的AirPlay模式，覆盖安装并打开本包。
2. 电视与iPhone连接同一家庭网络，保持电视测试界面前台。
3. 在相册单个本地视频／B站普通UP主视频的播放器里选择隔空播放，找 **小狗便利店投屏·AirPlay测试**。名称与设备标识已更新，避免继续选择旧的“直投测试”发现记录；配对状态单独保存。请关闭并重新打开手机的设备选择菜单。
4. 有画面后到“连接详情”查看实际方式：HTTP(S)／HLS是地址直投；“AirPlay视频流（兼容接收）”是发送端编码视频流，不能称为纯地址直投。新包也能接收控制中心屏幕镜像，这只是另一种入口，测试相册时仍使用相册自己的隔空播放。
5. 直投使用播放器暂停／进度控制；兼容视频流的暂停和进度由手机控制，电视点击画面或按方向键可唤出详情／结束按钮，约2秒收起，菜单键直接查看详情。返回结束当前接收，再返回退出。Home／离开停止接收，无后台待机。

## 实际改动

- 在独立服务中接回既有 VideoPipeline／AudioPipeline，处理编码视频、尺寸、音频格式、数据、清空、音量与结束事件；视频流使用独立Surface并按解码尺寸保持比例。
- 只有接收模块确实可处理视频流时启用 Screen功能位；仍保留Video／HLS。照片幻灯片／受保护视频能力不启用。mdns与server-info保持一致。
- 地址直投和编码流切换时停止旧播放器／旧解码器，避免声音重叠；旧流结束事件不结束仍在播放的地址直投。退出释放解码器和Surface。首个关键帧短暂等待Surface创建，防止短片首次出画面前丢掉唯一关键帧；旧媒体结束事件按本地会话代次隔离，避免关闭随后到达的视频流。
- 界面标记实际接收方式，有效地址直投次数为0并不等于没有视频流；另有视频流输出帧、音频输出和之前的阶段计数。诊断不显示完整媒体URL／令牌。

## 边界与验收

新增的是视频流兼容接收，没有新增苹果视频DRM、ALAC／音乐专用播放或照片幻灯片。仅收到音频而没有视频时，仍可能无画面；无法通过本机渲染器凭空补出发送端没有发来的画面。不能以镜像流可播放冒充所有App纯直投可用。

本机使用Android12 ARM64模拟器与合成视频检查地址播放、HLS、反向协商、发现、控制与换片；视频流检查输入经AirPlay形状调整的H.264数据，确认真实解码输出、AAC音频输出及直投→视频流→直投切换。视频流输入通过回调注入，未复现完整真实iPhone加密握手，模拟器无真人听音验收。原生检查10项、直投单元3项、镜像库单元52项均通过，Lint 0错误／11警告；最终哈希以随包验收JSON为准。

**这包不能标记“iPhone相册已修好”或“目标视频App已修好”。** 真机先验收相册是否出现新名称，再验收选中后的画面／声音。反馈需注明B站版本、视频类型、iPhone型号／系统、接收设备和新连接详情；无需反复尝试旧包。旧版横向彩条／长期同步问题独立待排查，本次没有其已验收修复。
