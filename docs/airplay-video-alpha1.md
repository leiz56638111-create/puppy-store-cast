# AirPlay 视频直投独立实验版 0.3.0-video-alpha1

这是主版以外的单独测试包，包名 `cn.local.livingroomcast.airplayvideo`，可以与 0.1.8 一起安装。仅用于测试视频 App 内的 AirPlay。主版 0.1.8 和横向彩条问题的修复验收不因本包发生变化。

## 安装与使用

1. 把 APK 放到 U 盘，使用电视文件管理器安装。最低 Android 7.0，ARM64／32 位 ARM；32 位目前仅编译检查。
2. 完全退出其他 AirPlay 接收软件，包括主版的镜像模式，再打开“小狗便利店投屏·视频直投测试”。电视与苹果设备连接同一家庭网络。
3. 请保持测试包前台打开。到视频 App 的播放器中点 **AirPlay**，选 **小狗便利店投屏·直投测试**。请勿使用控制中心的“屏幕镜像”，也不要选成 App 里的 Chromecast／DLNA 入口。
4. 手机可尝试暂停、继续、拖动和结束。电视点击画面或遥控器唤出播放器控制，操作栏约 2 秒隐藏；菜单键可查看连接详情。返回一次结束视频，再返回退出。Home／离开测试界面停止接收。

## 建议第一轮这样测

优先 Safari 普通网页视频、相册中单个本地视频、YouTube 免费普通视频，每次只试一段；国内 App 有 AirPlay 入口的也可加入。这里只是测试清单，**尚未确认上述 App 在真实苹果设备上兼容**。相册照片／精选幻灯片、音乐单独投送不属于本版范围。

每个来源记录：能否发现 → 能否连接 → 有无画面和声音 → 手机暂停／继续／拖动 → 连续换下一个视频 → 断开重新连接。初步通过后再连续看 10–20 分钟，留意无声、自动加速、声画不同步或横条；长时间验收需另行累计。

## 支持边界

接收可访问的 HTTP(S) 视频、普通 HLS，及发送端通过反向 HTTP／FCUP 协商的 HLS 播放列表，使用 Media3 播放。这是按协议实现的共同路径，没有按 App 名写死白名单。部分 App 不提供 AirPlay 或使用 DRM／额外登录／私有认证链路，不能承诺所有或大部分 App 成功。暂不支持 FairPlay 视频 DRM、音乐专用 ALAC、照片幻灯片和镜像播放。

连接详情只保留本次运行的状态，不显示完整视频地址或授权信息。真实来源的授权头／Cookie 转发和私有协议并未实现。视频直投时的清晰度由发送端给出的媒体与接收端解码能力决定；没有额外的 4K、HDR、60fps 或游戏低延迟保证。

## 已做的检查与复现

独立包构建、代码检查、请求边界单元检查；Android 12 ARM64 模拟器使用自制音视频测试 MP4／HLS、播放控制、换片、反向播放列表协商、实际 Bonjour 查询、停止／重开接收。声音检查依据解码输出计数，模拟器没有做真人听辨或电视声画同步验收。本轮原生 8 项、直投单元 3 项、镜像库单元 52 项均通过；Lint 0 错误／11 警告。安装包哈希随包验证报告记录。

复现原生检查：构建 `:direct:assembleDebug :direct:assembleDebugAndroidTest`，启动专用安卓模拟器后执行 `python3 tests/run_direct_video.py --serial emulator-XXXX`。需要 adb／ffmpeg／Python 3.12+；它只向指定模拟器安装实验包，临时提供 127.0.0.1:18099 合成媒体服务，结束后关闭媒体服务。真实苹果设备／真实 App 验收必须另外完成。
