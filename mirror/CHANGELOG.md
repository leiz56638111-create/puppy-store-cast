# 镜像实验版更新

## 0.2.0-mirror-alpha2 · 2026-10-21

用户反馈：iPad 的 YouTube、相册精选及单独视频，进入提示“正在以 AirPlay 方式播放”的状态后，电视画面仍正常，声音偶发消失；断连重连可以恢复，另有偶发自动加速。尚未采集故障当时的接收日志，不能断言具体触发路径或音频格式。

已在 alpha1 复现并修复：

- 音频同步解码器 flush 后错误调用 start，导致重置后失声。现在重建解码器与音频输出；通过代次及互斥管理，防止旧线程碰新资源。输出失败后，后续音频包触发限频重建。
- /info 等非媒体连接的打开／关闭会调用全局媒体开始／结束并重置时钟。现在仅持有媒体的连接计入会话，查询连接不会打断播放。
- 视频输出忽略时间戳，突发 45 帧数据在旧版只用 81 ms 播放。现在按本地时间与帧时间戳呈现，时间跳变／长时间积压时重新定基点；没有实现音频主时钟的完整声画同步。

补充：每次音频 SETUP 重新配置输出；PCM 输出采用解码器实际报告的采样率、声道及编码，支持部分写入；保留发送端音量与静音。此改动不等于已支持任意输入采样率，协议输入配置仍为 44.1 kHz 双声道。

播放中点画面或按遥控器方向／确认键打开连接详情，新增“恢复声音”。只重建音频，不断开视频会话；详情显示协商标志、格式、输入／输出计数、音量、输出参数、重建次数与最近错误。未协商或 ALAC 格式不会报告恢复成功。ALAC 解码仍未实现，不能把所有无声都认定为同一种原因。

本地：49 项单元、37 项 Android 11 ARM64 检查通过，Lint 0 错误／25 警告。新增连续 8 次重置、手动恢复与静音保留、重新 SETUP、媒体播放期间查询连接关闭、视频突发节奏、恢复声音按钮检查。AAC-LC 使用真实合成码流；AAC-ELD 仅配置接受测试。两种 ARM ABI 编译成功，32 位未运行。

安装包 versionCode 2，沿用镜像实验包的原签名及独立包名，可覆盖 alpha1。公开 DLNA 主应用 app/ 未改动。修复版尚未真实 Apple／索尼复测，暂未上传 GitHub。

安卓接口依据：[MediaCodec.flush](https://developer.android.com/reference/android/media/MediaCodec#flush()) 与 [AudioTrack.flush](https://developer.android.com/reference/android/media/AudioTrack#flush())。
